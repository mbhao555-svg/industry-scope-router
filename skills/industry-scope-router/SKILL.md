# 行业 / 产业链 调研路由器

**先判层面 → 判不出就问 → 按类型出对应报告。**

> **本技能的独有职责是"路由"**：判类型、生成对应骨架、守住"两层判断不得混用而不声明"这条铁律。

## 二、类型判定判据表（核心）

### 2.0 先记住：两者不是包含关系，而是两条正交的轴

**判定之前必须理解这一点，否则下面的词表只能死记。**

| | **行业** | **产业（产业链）** |
|---|---|---|
| **按什么切** | **统计分类口径** | **价值流转** |
| **边界谁定** | 官方分类标准（如 GB/T 4754） | 分析者按上下游划定 |
| **有无官方代码** | **有** | **无**——产业是分析概念，不是统计单位 |
| **数据从哪来** | 官方与机构**汇总统计** | 必须**自己按环节拆** |
| **回答什么** | 这个行业**多大、多少家、增速多少** | 这条链上**钱在哪一段、谁有定价权** |

**关键**：**行业与产业不是包含关系**（不存在"行业 ⊃ 产业"或"产业 ⊃ 行业"）——**它们是穿过同一批企业的两条不同的坐标轴**（两轴正交）。

**实证**：一家企业**既是**某个行业代码下的统计单位，**也是**某条产业链上的一个环节点。所以：
- **"预制菜"**：有完整的上中下游（是**产业**），但在行业分类里**无专门代码** → **有产业，无行业**
- **"虾滑"**：同理无专门代码，但能明确归入 C136 水产品加工 → **归属清晰，行业报告可出**
- **"新能源汽车"**：有明确的行业代码与官方统计 → **行业与产业两条轴都成立**

> ⚠️ **本节的词表是"操作化版本"**；概念的权威定义见 `references/行业与产业-定义.md`。**若表述冲突，以定义文件为准。**


### 2.1 第一层：显式词（优先，命中即定）

| 命中这些词 | 判定 |
|---|---|
| **产业链、产业、供应链、价值链、上下游、上游/中游/下游、环节、链条** | ✅ **产业链调研报告** |
| **行业、行业前景、行业格局、行业规模、这行生意** | ✅ **行业调研报告** |

> ⚠️ **两词同时出现时**（例如用户写成"某行业 + 产业链"这种混写）：**以问题指向为准**——见 2.2。若仍不明，按 2.4 询问。

### 2.2 第二层：问题指向（隐式，看"他到底想知道什么"）

| 用户真正想知道 | 判定 |
|---|---|
| 这个行业**整体**值不值得进 / 前景如何 / 处于什么阶段 | ✅ **行业调研报告** |
| 市场规模多大、增速多少 | ✅ **行业调研报告** |
| 渗透率多少、还有多少空间 | ✅ **行业调研报告** |
| 集中度如何、几家头部、格局是否收敛 | ✅ **行业调研报告** |
| 政策对这个行业是鼓励还是限制 | ✅ **行业调研报告** |
| **钱在哪一段** | ✅ **产业链调研报告** |
| **上游/中游/下游**哪段好 | ✅ **产业链调研报告** |
| 哪一段有**定价权** / 哪一段是**利润洼地** | ✅ **产业链调研报告** |
| 某**环节**值不值得做 / 某**环节**的竞争 | ✅ **产业链调研报告** |
| 我该做链上的哪个位置 | ✅ **产业链调研报告** |
| 某个**零部件/材料/设备**能否国产替代 | ✅ **产业链调研报告** |

### 2.3 第三层：先决条件核查（**必须在判定前查，否则会产出不成立的报告**）

**🔴 执行时机（易错）**：**只要问题里出现了具体对象名（行业名／产业名／品类名），就先做本核查，不要等类型判出来**。理由：若行业报告这条路数据基础不足，必须**在询问用户之前就把限制说出来**，否则用户可能在询问环节选了"行业"，随后才被告知做不了。

#### 2.3.1 ★ 正确的判据：归属路径是否清晰 ＋ 目标行业统计是否可达

**⚠️ 本判据经实测修正**：**原判据是"该对象有无专门行业代码"，这是错的——问错了问题。**

反例（实测）：**"虾滑"也没有专门行业代码**，但它有明确可查的归属路径（水产品加工／速冻食品制造），**且这两个行业都有官方统计**，因此**行业报告是可行的**。而"预制菜"同样无专门代码，却因**归属边界本身有争议**（"预包装菜肴"是否含糜状半成品未定）导致**统计基础不足**。

| 核查项 | 结果 | 处置 |
|---|---|---|
| **① 有无专门代码？** | 有 | 直接用该代码取数 |
| | 无 | **继续查②**——**不得直接判"不能出行业报告"** |
| **② 能否明确归入某个有效代码？** | 能（归属路径清晰、逐条可查） | ✅ **可出行业报告**——用**主归属行业**的汇总统计；在定义节**注明产品无专门代码、所归代码及依据**；**代码归属标"待核实"** |
| | 不能（边界本身有争议，如"算不算该行业"未定） | 🔴 **行业报告数据基础不足**——须**在询问前告知用户**，并建议改为产业链报告（预制菜即此例） |
| **③ 目标行业有无官方汇总数据？**（规上营收／企业数／产量） | 有 | ✅ 行业级结论可用；但**产品级数字仍多为机构估算**，须标"口径不明" |
| | 无 | ⚠️ 用机构估算，规模标"估算／口径不明"，**阶段置信度降为中** |
| **④ 该对象是否真是一条链？**（有可辨认的上中下游） | 否（如纯服务、纯平台） | ⚠️ 产业链报告不适用 → **改用替代拆法** |

#### 2.3.2 两条归属路径并存时怎么办

**实测（虾滑）**：同一对象有两条归属路径且代码不同——

| 路径 | 代码 | 依据 |
|---|---|---|
| 按原料与工艺（**主归属**） | C136 水产品加工业 | 主原料为虾、工艺为水产品调制速冻；且 C1432 明确排除"冷冻水产品，列入 C1361" |
| 按企业年报自述 | C1432 速冻食品制造 | 上市公司年报自述（因执行 SB/T 10379《速冻调制食品》） |

**处置规则**：

1. **取主归属**（按分类逻辑成立的那条），并在定义节写明两条路径与取舍理由
2. **两条路径会造成口径混淆时，分别标注两个版本的数字**，不得混用
3. **整个代码归属标"待核实"**，并写明建议核实方式

#### 2.3.3 由本核查直接改类型的两种情形

| 情形 | 处置 |
|---|---|
| 用户问**行业**层面，对象**归属边界有争议**（2.3.1 第②项判"不能"） | **不要直接产出报告**——先用 2.4 的模板告知，**等确认**；若用户仍坚持，规模数字标"估算、口径不明"，并声明**行业级结论无官方统计基础** |
| 用户问**行业**层面，对象**归属清晰**（2.3.1 第②项判"能"） | ✅ **直接产出行业报告**——定义节注明无专门代码、所归代码与依据，并把代码归属标"待核实" |
| 用户问题**笼统**（类型未定），且对象**归属边界有争议** | **在询问模板前加一句限制说明**，让用户知道"选项 A 行业调研对本对象数据基础不足" |

### 2.4 判不出时：向用户询问（**不要猜**）

**触发条件**（任一即问）：

| # | 情形 | 例子 |
|---|---|---|
| 1 | 问题**笼统**，两层都说得通 | 用户直接问"X能不能投"而**未说明要哪种报告**时（若已加载 `industry-deep-research` 且用户要完整调研，由该技能处理；本技能只在**用户要求先判层面**时介入） |
| 2 | 只给了**一个名称**，无任何动词或关注点 | "新能源汽车" |
| 3 | 显式词**冲突**，无法判断指向 | "某行业+产业链的机会" |
| 4 | 先决条件核查**结论改变了类型**（如无行业代码） | 用户问"预制菜行业前景" → 无代码 → **须先告知再确认** |

**询问模板（照用，含三个选项与代价）**：

> 我需要先确认一下调研层面，因为**行业调研与产业链调研回答的不是同一个问题**：
>
> | 选项 | 回答的问题 | 报告会给出 |
> |---|---|---|
> | **A 行业调研** | 这个行业**整体**值不值得进 | 行业阶段、渗透率、集中度、行业级结论 |
> | **B 产业链调研** | 这条链上**投哪一段、绕开哪一段** | 环节级利润分布、逐环节出清、逐环节落点 |
> | **C 两者都要** | 整体与环节都要 | 两份内容合并，并附**两层关系声明** |
>
> **你要哪一个？**（若你关心的是"这门生意整体如何"，选 A；若关心"该做链上哪个位置"，选 B。）

**若对象无行业代码且用户问题笼统 —— 询问模板前必须先加这句**：

> ⚠️ **先说明一个限制**：**「X」在《国民经济行业分类》中没有对应代码**，因此**选项 A（行业调研）在数据上没有官方统计基础**——市场规模、渗透率、集中度都只能用机构估算并标注"口径不明"。**若你要的是可靠的行业级结论，本对象不适用；建议选 B（产业链调研）。**

**先决条件导致类型改变时的模板**：

> ⚠️ 先说明一个限制：**「X」在《国民经济行业分类》中没有对应代码**，因此**行业级结论（市场规模、渗透率、集中度）没有官方统计基础**——行业调研报告在数据上不成立。
>
> 因此我建议改为**产业链调研**：直接看它的上游／中游／下游，给出各环节的利润分布与可投性。**你确认吗？**（若你坚持要行业层面，我只能用机构估算数据，并会把全部规模数字标注为"估算、口径不明"。）

## 三、两种报告的结构骨架

### 3.1 行业调研报告骨架

**中心问题**：**这个行业整体值不值得进？**

```
摘要（一句话结论 + 进/不进/等什么条件）
一 定义与统计口径        分类代码表 + 官方边界 + 标准切分点 + **六项重点方向覆盖度表**（见 3.1.4）
二 市场规模与增长        多口径并列（不取平均）+ 增速序列
三 行业阶段判定          ★核心：五指标投票 → 渗透率校准 → 共线检查 → 冲突裁决 → 阶段标签 + 置信度
四 渗透率与空间          档位 + 是否触发硬规则 + 国际对照
五 竞争格局与集中度       CR3/CR5/CR10 及趋势 + 头部企业对比
六 行业级壁垒与关键依赖    ★：技术壁垒（行业进入门槛）＋ 认证/验证周期 ＋ 关键零部件/材料的进口依赖与国产替代（见 3.1.1）
七 区域分布              ★【条件节】行业有明显地理集聚时必加；无集聚时写明"无显著集聚"并跳过（见 3.1.2）
八 政策与监管            政策沿革表 + 实际约束（鼓励/强制/许可）
九 机会点、进入门槛与竞争策略  ★：切入点 → 可投性 → 门槛 → **新进入者的差异化策略**（见 3.1.3）
十 趋势与风险            表格化 + 先行指标
十一 行业级投资结论      进/不进/等什么条件 + 失效条件
附录 A 判据冲突裁决记录
附录 B 信息缺口清单
附录 C 数据疑点（只列不改）
方法与数据来源说明
```

**必备产出（缺一即不合格）**：① 阶段标签 + 置信度 ② 渗透率档位 ③ 集中度 ④ **机会点与竞争策略（含新进入者的可行路径）** ⑤ 行业级结论含失效条件

**⚠️ 不要求的**：环节级利润分布、逐环节出清档位、投资含义矩阵的逐环节落点

#### 3.1.1 行业级壁垒与关键依赖（第六节用）

**为什么设在行业层**：环节层的壁垒回答"**这段能不能被替代**"；行业层的壁垒回答"**这门生意别人能不能进来抢**"。**两者不可互相替代。**

| 维度 | 问什么 | 判据 |
|---|---|---|
| **技术壁垒（行业级）** | 行业整体的技术门槛在哪？是核心工艺、专利，还是设备与材料？ | **行业是否整体依赖境外技术**——若是，行业级护城河不在企业手里 |
| **认证／验证周期（行业级）** | 进入这个行业需要多长的资质与认证周期？ | 周期越长，**新进入者的时间成本越高**（如医疗器械注册证） |
| **关键零部件／材料依赖** | 行业整体依赖哪些境外零部件或材料？ | 决定**整个行业的供给安全与成本敞口** |

**关键依赖字段表（第六节必填）**

| 字段 | 要求 |
|---|---|
| 依赖项名称 | 具体到零部件／材料／工艺／软件 |
| 当前进口依赖度 | 数字 + 来源 + 年份；**无数据就写"未取到"** |
| 海外主导方 | 谁掌握 |
| 国内参与者 | 谁在做、进展到哪一步 |
| **国产替代进度** | 实验室／中试／小批量／量产／已替代 |
| 判断 | **行业级卡点在哪、能否替代**——不得只说"存在卡脖子" |

> ⚠️ **与产业链报告的区分**：本节写**行业整体**的壁垒与依赖；**具体卡在哪一环节**属产业链报告（3.2.3）。

#### 3.1.2 区域分布（第七节，条件节）

**触发条件**：行业有**明显地理集聚**时必加；**无集聚时写明"本行业无显著地理集聚"并跳过**，不要留空节。

**区域对照表（必用形态）**

| 区域 | 核心区 | 规模指标（**口径须统一或逐格标注**） | 主导品类／环节 | 国家级头衔 | 升级方向 | 代表企业 | 依据 |
|---|---|---|---|---|---|---|---|

**四条填写纪律**（与集群对照表一致）

1. **规模列口径必须统一**（全用产值／全用加工能力／全用企业数），**不一致就逐格标注**——混用口径等于没有这一列
2. **"国家级头衔"单列**（国家现代农业产业园／优势特色产业集群／骨干冷链物流基地等）——这是**政策资源**
3. **"升级方向"是关键列**——比"它有多大"更有判断价值
4. **表下写 2–3 条横向结论**——只给表不给结论等于把分析推给读者

**行业级区域分布要多答一个问题**：**行业的地理集中度是否本身就是壁垒**？（如某行业全部产能集中在两三个省 → 新进入者选址即受限）

#### 3.1.3 机会点、进入门槛与竞争策略（第九节）

**⚠️ 实测教训**：本技能首版**只给行业级可投性判断，没给"新进入者该怎么打"的策略判断**——而后者往往才是读者最需要的（尤其"面对行业巨头，新玩家怎么办"）。

**（1）机会点表（每个切入点按六项写全）**

| 字段 | 要求 |
|---|---|
| **切入点名称** | 具体到品类/渠道/区域，不要写"高端化"这类空话 |
| **为什么是机会** | **需求/供给/政策/格局**四类依据，**各带来源** |
| **可投性** | 环节或标的类型、一级或二级市场可及性、退出路径 |
| **门槛** | 资金／资质／技术／渠道／规模 |
| **当前竞争强度** | 带依据（集中度、玩家数、价格战迹象） |
| **置信度** | **四档原词**：高／中／中低／低——**不得自造"低—中"等未定义档位** |
| **反面证据** | ⚠️ **什么情况下这个机会不成立** |

**（2）进入门槛与潜在挑战表**

| 挑战 | 具体表现 | 可规避性 | 依据 |
|---|---|---|---|

可规避性填 **可／部分／不可**——**不可规避的挑战要直接说明它构成否决项**。

**（3）★新进入者的竞争策略（本节最容易被省略、但对读者最有价值）**

**必须回答**：**面对已有巨头，新进入者的可行路径是什么？**

| 情形 | 可行策略 | 判断依据 |
|---|---|---|
| 巨头靠**规模与成本**领先 | **差异化产品**（避开正面价格战）——如更高质量等级、更细分人群/场景、更短保质期/更新鲜 | 若该环节规模经济成立（头部单位成本显著低），正面拼成本必败 |
| 巨头靠**渠道与品牌**领先 | **新渠道或新场景**（避开已锁定的货架） | 若渠道已被占满 |
| 巨头**尚未覆盖**的细分 | **先占细分**，做到该细分的份额领先 | 细分增速显著高于整体 |
| **行业标准刚落地** | **抢先达成合规/更高标准**，把标准变成溢价凭证 | 国标实施后，合规是入场券；**若能把"超过标准"做成卖点，则是差异化** |

**输出要求**：**给出 2–3 条可行策略**，每条写明①对应哪个切入点 ②为什么这条路对巨头不划算或巨头做不到 ③**所需资源** ④**失效条件**。

**禁止**：只写"要差异化"而不说**差异化在哪一点、为什么巨头不跟进**——那是空话。

#### 3.1.4 六项重点方向覆盖度（第一节，**每份必填**）

**本报告默认覆盖六个方向**：市场规模 · 竞争格局 · 技术演进 · 政策变化 · 商业模式 · 投融资动态。

**逐项声明覆盖状态，未覆盖的写"未覆盖"**——不得留空、不得暗示"已查无"。

| # | 重点方向 | 本报告对应节 | 覆盖状态 | 检索量 |
|---|---|---|---|---|
| 1 | 市场规模 | 二 | | |
| 2 | 竞争格局 | 五 | | |
| 3 | 技术演进 | 一·5 沿革 ＋ 六 壁垒 | | |
| 4 | 政策变化 | 八 | | |
| 5 | 商业模式 | 一·5 沿革（渠道结构／客户集中度／单位经济） | | |
| 6 | 投融资动态 | 五·3 竞争动态 ＋ 十一 | | |

> ⚠️ **"未覆盖" ≠ "已查无"**——未覆盖要写明**为什么**，并列入附录 B。
> ⚠️ **不得把六个方向写成六节**——它们**映射到现有骨架的对应节**；**六方向是覆盖度要求，不是章节结构**。

#### 3.1.5 术语与代号说明（**条件必填**）

🔴 **触发条件**：**报告正文一旦使用了 M／S 代号，本节必填**——否则读者看不懂。

> ⚠️ **实测问题**：曾出现正文用了 M4／M5 而全报告**没有任何代号定义**的情况。

### 3.2 产业链调研报告骨架

**中心问题**：**这条链上投哪一段、绕开哪一段？**

```
摘要（一句话结论 + 可投/规避清单，逐环节）
一 链的界定与环节结构    上中下游切分 + 链条结构（纯文本树/箭头，不用 Mermaid） ＋ **六项方向覆盖度表**（见 3.2.5）
                        + 每环节结构字段（见 3.2.1）
二 环节级利润分布        ★核心：环节 → 毛利率 → 收入占比 → 来源 → 样本量
三 逐环节竞争与集中度     每环节自己的集中度（各环节可完全相反）

附录 A 判据冲突裁决记录

```

**必备产出（缺一即不合格）**：① 环节级利润分布 ② 逐环节出清档位 ③ **逐环节技术壁垒** ④ 逐环节落点含失效条件

**⚠️ 不要求的**：行业阶段标签、渗透率、行业级 CR、行业级市场规模

#### 3.2.1 第一节的"每环节结构字段"（必填）

**为什么设这一节**：利润与出清回答"**这段赚不赚钱、能不能收敛**"；结构字段回答"**这段靠什么赚钱、能不能被替代**"。**缺它，环节结论无法解释也无法验证。**

| 字段 | 要求 |
|---|---|
| 核心产品 | 这个环节交付什么 |
| 关键投入 | 依赖什么（原料／设备／技术／数据） |
| 技术路线 | 主流方案及其分野 |
| 代表企业 | **必须有来源**，不凭印象补齐 |
| 主要客户 | 卖给谁、客户集中度如何 |
| 产品流向／价值流向 | 与谁交易、钱往哪边走 |
| **认证与验证周期** | 导入需要多久、门槛是什么（**决定护城河宽度**） |
| 供需格局 | 偏紧还是过剩 |
| 议价能力 | 强／中／弱 + 依据 |
| 替代风险 | 谁可能替代它 |
| **证据状态** | 已核实／待核实／冲突 |

#### 3.2.2 壁垒的三层判断（第五节用）

| 层 | 问什么 |
|---|---|
| **技术层** | 是否掌握核心工艺／专利？关键设备与材料能否自主？ |
| **规模层** | 头部单位成本是否显著低于中小（**差 ≥10%**）？ |
| **认证／渠道层** | 认证周期多长？客户切换成本多高？渠道是否被占 |

**判据**：三层皆弱 → 该环节**利润再厚也不可持续**（会被新进入者压平）。

#### 3.2.3 国产替代字段（第六节用）

| 字段 | 要求 |
|---|---|
| 卡点名称 | 具体到零部件／材料／工艺步骤 |
| 当前国产化率 | 数字 + 来源 + 年份（**无数据就写"未取到"**） |
| 海外主导方 | 谁掌握 |
| 国内参与者 | 谁在做、进展到哪一步 |
| **替代进度** | 实验室／中试／小批量／量产／已替代 |
| 判断 | **能否替代、卡在哪**——不得只说"存在卡脖子" |

> ⚠️ **产业链报告若缺某个环节的分部数据 → 该环节结论不成立**，须标"需另行取证"，**不得给可投性判断**。

#### 3.2.4 环节区域分布（第九节，条件节）

**触发条件**：**链上有环节存在明显地理集聚**时加；无集聚则写明"无显著集聚"并跳过。

**与行业级区域分布的区别**（不要写成同一节）：

| | 行业级（3.1.2） | 产业链级（3.2.4） |
|---|---|---|
| 看的单位 | **行业**在哪些区域集聚 | **链上哪个环节**集中在哪 |
| 回答 | 行业地理集中度是否构成壁垒 | **是否某环节被某地垄断**（→ 议价权与风险） |
| 典型价值 | 选址与政策资源 | **识别"单点依赖"风险**——若上游只集中在一地，该环节的供给风险高 |

**环节区域对照表**

| 环节 | 主要集聚区 | 规模指标（口径标注） | 是否形成集群 | 代表企业 | 单点依赖风险 | 依据 |
|---|---|---|---|---|---|---|

**必答的一个问题**：**有没有哪个环节是"一地独占"**？若是，**该环节的议价权与断供风险都要单列**——这是产业链报告特有的判断。

#### 3.2.5 六项方向覆盖度 与 术语与代号说明（产业链版）

**覆盖度表按环节维度映射**（产业链版**不写行业级市场规模**）：

| # | 重点方向 | 产业链版对应节 |

| 5 | 商业模式 | 一·2 关键投入／主要客户／议价能力 ＋ 七 落点 |

### 3.4 术语禁写（写报告时逐条核对）

> **这一节直接防"行业／产业不分"**——实测过：把环节说成"行业的上游"、把产业增速说成"产业增速"，都是概念错位。

| # | 禁写 | 为什么错 | 改为 |
|---|---|---|---|
| 1 | **行业产业链** | 同义反复，且两层混在一词里 | 依类型写"**行业**"或"**产业链**" |
| 2 | **某某行业的上游／中游／下游** | 行业是统计分类，**没有上下游** | "某某**产业**的上游／中游／下游" |
| 3 | **产业链的行业阶段** | 产业链不判行业阶段 | 行业报告写"**行业**阶段"；产业链报告**不写阶段** |
| 4 | **各环节的行业集中度** | 环节属产业层 | "**各环节**的集中度" |
| 5 | **产业增速** | 产业**无官方增速** | "**行业**增速"或"该**环节**增速" |
| 6 | **行业环节** | 环节属产业层 | "产业**环节**"或"**链上环节**" |
| 7 | **产业链市场规模** | 产业链无官方市场规模 | "链上各环节收入之和"或"该**行业**市场规模" |
| 8 | 把**渗透率**用于单个环节 | 渗透率分母是行业／品类总量 | **只说行业层渗透率**；环节层用"导入进度／客户渗透"等**另定义的指标** |

**自检**：交稿前全文搜这 8 个禁写模式，**命中即改**。

---

**实测教训**：已产出的 6 份报告中 **5 份是"混合报告"（既有行业级阶段又有环节级落点），而无一加过声明**——读者看到"行业判成长期"又看到"某环节判成熟期"，**无法判断是否自相矛盾**。

### 3.5 🔴 过程性标注禁写（读者不需要知道"我怎么处理的"）

**⚠️ 实测教训**：报告正文出现过 `（应纳入，但有两处边界）`、`（必须声明）`、`（按 2.3.1 判据：归属路径清晰 → 行业报告可出）`、`（缺一即不合格）` 这类**括号标注**——**它们讲的是"我为什么这样处理"，不是行业事实**，对读者是噪音。

| # | 禁写（过程性标注） | 改为 |
|---|---|---|
| 1 | `（应纳入，但有两处边界）` | **删掉**；把边界写成正文事实（如"该产品符合 X 要件，但 Y 条款构成例外"） |
| 2 | `（必须声明）`／`（须为引用）` | **删掉**——声明就直接声明，不用预告 |
| 3 | `（按 2.3.1 判据：…）`／`（见第 X 节）` | **删掉**——读者不需要规则编号；正文自然承接即可 |
| 4 | `（缺一即不合格）`／`（条件节）` | **删掉**——那是**技能的填写要求**，不是报告内容 |
| 5 | `（逐环节）`／`（口径标注）` 等自述 | 若能看懂就删；确需限定则并入句子 |
| 6 | `（推断）`／`（估算）` 单挂在段末 | ⚠️ **这类要保留但须规范**——统一写成"**类型：推断**"融入表述，或放入表格的"类型"列，**不散落** |

**判据（一条可操作的）**：**括号里的内容如果换成"任何读者都不需要知道"，就删。**

**自检**：交稿前扫以下模式。

```powershell
$pats = '（应纳入|（必须声明|（须为|（按 \d|（见 \d+\.|（缺一即不合格|（条件节|（见第 \d+ 节'
[regex]::Matches($doc, $pats).Count   # 须为 0
```

> ⚠️ **两处会误报的合法用法，扫描时须排除**：
> 1. **元信息字段内容**里的"（本报告…）"——如 `特别关注点：未指定（本报告默认关注投资可投性）`。**元信息是在描述报告本身，属合法**。
> 2. **正文在解释报告自身口径**时的"（本报告采用 X 口径）"——**这是读者需要的**，属合法。
>
> **判据仍是**：括号里的内容如果换成"**任何读者都不需要知道**"，就删。**元信息与口径声明恰是读者需要的**，故不属过程性标注。

### 3.6 排版纪律（引用块、元信息、长行）

| # | 规则 | 说明 |
|---|---|---|
| 1 | **元信息块（类型／判定依据／先决核查）必须表格化** | ⚠️ 实测：曾把"调研类型＋判定依据＋先决核查四步"**挤在一个引用块里 9 行**，读者难读。**改为：** 类型与依据用一句话；**先决核查用 3 列表格**（核查项｜结果｜结论） |
| 2 | **引用块（`>`）不得超 150 字符** | 引用块**不享有长行豁免**——它与正文一样要守宽度纪律；过长则拆行或改为表格 |
| 3 | **引用块不超过 5 行连续** | 超了就说明它该是表格或正文 |
| 4 | **每个 `>` 行独立成行，不要一行塞多个要点** | 每个要点一个 `>` 行 |
| 5 | **元信息不得含过程叙述** | 元信息只写"报告是什么"，不写"我怎么做的"（见 3.5） |

### 3.7 🔴 口径分层：先判"是不是同一层级"，再决定"冲突还是分层"

**⚠️ 实测教训（一次真实报告的框架被推翻）**：
报告里写"虾滑市场规模有两个冲突口径：500 亿元 vs 173.1 亿元，相差 2.9 倍"——
**这个框架本身是错的**。深挖后查明：

| 数字 | 真相 |
|---|---|
| **500 亿元** | **无任何机构署名**；是**餐饮终端消费额／TAM（潜在空间）口径** |
| **173.1 亿元（2026E）** | **艾媒咨询的预测**（出厂／食品口径）；所谓"食品伙伴网口径"只是**无署名转引** |

**两者不是"冲突"，是"两个不同层级"**——**终端口径天然是出厂口径的数倍**（实测终端加价约 4.8–5.0 倍）。

#### 3.7.1 判据：先分三种情形，再决定怎么写

| 情形 | 特征 | 写法 |
|---|---|---|
| **① 口径分层（不是冲突）** | 数字差异可由**统计层级**解释（终端／出厂／TAM／零售） | **分别标注层级**，**不得写成"冲突"**；并**给出层级间的换算关系或加价倍数**（若有实证） |
| **② 真冲突** | 同一层级、同一基准年、**方向相反或差异过大且无层级可解释** | 按冲突处理：**并列、不取平均**，写明差异与可能成因 |
| **③ 同源（伪独立）** | 两个数字**同一来源**，或多个媒体**互相转引** | **按共线处理，不得当作两个独立来源**；须回溯到最早出处 |

#### 3.7.2 三条必做动作

1. **回溯到最早出处，不要引用转引**——实测：同一批媒体把"2022 年 100.6 亿（出厂）"与"2022 年 500 亿（终端）"**混拼成"从 100.6 亿跃升至 500 亿"**；引用转引会继承这个错误
2. **检查署名**——**无机构署名的数字要显式标注"无机构署名"**，不得挂到某机构名下
3. **检查层级**——数字超出同层级合理倍数（如出厂口径出现 5 倍差）时，**先怀疑层级不同，而不是"口径冲突"**

#### 3.7.3 术语纪律

| 禁写 | 改为 |
|---|---|
| "两个冲突口径相差 N 倍" | 先判层级；**是分层就写分层**，是冲突才写冲突 |
| "某机构口径 X 亿"（该数字无署名） | "**无机构署名**，常见引用为「X 亿」，疑为 Y 层级口径" |
| "从 A 跃升至 B"（A、B 不同层级） | **分别标注层级后**再作对比；**不得直接跨层级比较或相减** |

### 3.8 🔴 参数分级、结果精度与渗透率口径

#### 3.8.1 参数六分类（每个输入量单独登记一行）

**凡是参与计算或判断的输入量——包括减项（出口、库存变化）与系数（占比、更换率、执行率、类比调整系数）——都必须逐个登记并标性质。**

| 参数性质 | 含义 | 判断类型 |
|---|---|---|
| **观测** | 材料直接给出的原始值 | `[事实]` |
| **换算** | 原始值经单位、价格、汇率、时间或统计转换 | `[计算]` |
| **估计** | 有材料支撑、但需研究者判断的推算 | `[推断]` |
| **代理** | 目标参数缺失时使用的可解释替代量 | `[情境]` |
| **假设** | 为情景或预测明确设置的研究条件 | `[情境]` |
| **待核实** | 缺失或冲突输入，**不作确定核心参数** | `[待核实]` |

**登记要求**：数值/区间 · 单位 · 地域 · 数据所属期 · 定义/分母 · 性质 · 判断类型 · 材料状态 · 来源定位 · **来源原值 → 必要换算 → 模型参数 → 结果** 的转换步骤。

> ⚠️ **不得只列机构名称**——必须留出可复算的换算链。
> ⚠️ **本轮计算结果不得反过来充当本轮输入证据**。

#### 3.8.2 结果精度：有效位数不超过链条上最弱的那个参数

| 情形 | 表达方式 |
|---|---|
| 链条最弱参数是观测/换算 | 按该参数精度给结果 |
| 关键比例是**估计值** | **两位有效数字或区间**，不制造伪精度 |
| 关键参数是代理/假设 | **必须给区间或情景**，不得给单点确定值 |

**中间计算用未取整值，展示值与计算值分开。**

#### 3.8.3 渗透率必须先分清「存量」还是「流量」（★易错）

| 概念 | 定义 | 回答什么 | 常见别名 |
|---|---|---|---|
| **渗透率（存量）** | **已采用客户数 ÷ 适用客户数** | 到现在**一共装了多少** | 覆盖率、普及率、累计采用率、装机率 |
| **本期采用率（流量）** | **本期启动采购的客户数 ÷ 适用或可服务客户数** | **本期有多少客户在买** | 本期渗透率、当期新增 |

> 🔴 **两者不可互换**：**用存量渗透率去算本期新增，会把历年累计的采购都算进本期**。
> **换算关系**：`适用客户数 = 已采用客户数 ÷ 渗透率`；`已采用客户本期贡献 = 已采用客户数 × 本期客均支出`。
> ⚠️ **客户数与金额不能在同一条式子中互相还原。**

**做阶段判定时的用法**：
1. **先声明本次用的是存量还是流量**
2. **口径不明者不得用作渗透率**（"消费者意愿调查""偏好排名份额""渠道覆盖率"**都不是渗透率**）
3. 取不到有效读数就**如实留空并说明**，**不触发渗透率硬规则**
4. 渗透率是**行业级**概念，**不得跨层套用到单个环节**

## 四、🔴 强制规则：两层判断混用时必须声明


### 4.1 判定：什么算"混合报告"

**同时出现**以下两类内容，即为混合报告：

| 类别 | 标志 |
|---|---|
| 行业级 | 行业阶段标签／渗透率／行业级 CR／行业级市场规模 |
| 环节级 | 环节级利润分布／逐环节出清档位／逐环节落点 |

### 4.2 三种合规做法（择一）

| 做法 | 要求 |
|---|---|
| **① 纯行业报告** | **不出现环节级结论**；若提到环节，只作"结构性说明"并注明**不构成环节判断** |
| **② 纯产业链报告** | **不给行业阶段标签**；**渗透率不出现**（若必须提，标"行业级指标，仅供参考，不用于环节判断"） |
| **③ 混合报告** | **必须加 4.3 的声明段** |

### 4.3 混合报告的标准声明段（可直接复制）

> **关于本报告两个层面判断的关系**
>
> 本报告给出 **①行业级**阶段判定（基于全行业汇总数据：增速、企业数量、渗透率、政策口径）与 **②环节级**可投性判定（基于各环节分部财务数据与出清机制）。
>
> **两者不矛盾，也不可互相推导**——行业阶段回答"这个行业整体处于什么周期位置"，环节落点回答"这条链上哪一段能投"。
>
> **数据不得跨层使用**：行业判定只用行业级数据；环节判定只用环节级数据。**渗透率校准仅适用于行业层，未跨层套用到任何环节。**
>
> 因此本报告可能出现"**行业判成长期、某环节判成熟期**"的并列结论——**这是两个层面的正常差异，不是自相矛盾**。

### 4.4 交稿前必查七项（缺一不得交稿）

| # | 检查 | 不通过则 |
|---|---|---|
| 1 | 本报告是行业／产业链／混合中的哪一种？**类型明确吗**？ | 回到第 2 节重判 |
| 2 | 若是混合，**4.3 声明段在吗**？ | 补上 |
| 3 | 有无**把行业数据用到环节结论**上？有无**把渗透率用到环节**上？ | 删掉该依据，或补环节级证据 |
| 4 | **八个禁词扫描**是否全为 0？（改造／本版／原报告／表格化／★／前版／旧版／上版） | 逐个清零 |
| 5 | 🔴 **网站链接总数是否 ≥ 100**（上限 500）？ | **低于 100 须继续检索，不得交稿**——见 `references/检索作战包.md` 的 1.1–1.2 |
| 6 | **用了 M／S 代号吗？用了 → 「术语与代号说明」节在吗**？ | **补上**——否则读者看不懂（见 3.1.5／3.2.5） |
| 7 | **六项重点方向的覆盖状态表填了吗**？"未覆盖"的是否写明了原因？ | 补填；未覆盖项列入附录 B |

> ⚠️ **禁词的两处领域义例外**：「**改造产线／改造工艺／改造设备**」属产业术语，**不算残留**；「原报告」若指**外部原始报告**，改为「报告原文」以消歧义。

**禁词扫描（可执行）**

```powershell

    Where-Object { .Substring([Math]::Max(0,.Index), 6) -notmatch '改造(产线|工艺|设备)' }
"残留 $($hits.Count) 处（须为 0）"
```

> ⚠️ **呈现层检查本技能自带**（3.5 过程性标注禁写／3.6 排版纪律／`assets/report-template.md` 的 3.1–3.6）——**不依赖其他技能**。

## 五、执行流程

```
① 读问题
      ↓
② 【先做】对象核查（2.3）——问题里有具体对象名就先查归属路径与统计可达性

      ↓

      ↓ 未命中
④ 问题指向判定（2.2）——能定则定
      ↓ 仍不能定，或②判定统计基础不足
⑤ 用 2.4 模板询问用户（**若②有争议，须在选项表前先写限制说明**）→ 等确认
      ↓
⑥ 按确认的类型选骨架（第三节）；
      若两者都要 → 用混合骨架并加 4.3 声明段
      ↓
⑦ 【检索】读 `references/检索作战包.md`，按 1.1–1.2 执行：
      网站链接 100–500 个；至少 40 个 web_fetch 打开原文；至少 20 个一手来源
      F10 环节取数 → 该文件 1.5 节（含跨维度相加的头号陷阱）
      ↓
⑧ 【判定】按需读判据文件（本技能内置，不必外求）：
      阶段／渗透率／出清／投资含义 → `references/阶段判定与投资含义.md`
      产业链拆解／利润池／M1–M5／S1–S6 → `references/产业链与出清机制.md`
      来源分级／双源／冲突处理 → `references/来源核验与证据台账.md`
      ↓
⑨ 【成稿】按 `assets/report-template.md` 对应模板填写
      ↓
⑩ 交稿前查 4.4 五项（含链接数 ≥100 与八个禁词）
```

**执行纪律**：

3. 🔴 **检索量不得低于 100 个网站链接**——低于下限的报告会出现大量"未取到"；**报不出链接数即交稿不合格**
4. **规则单一权威**——阈值与判据只写在 `references/` 下；SKILL.md 与模板只写"做什么/填什么"，**不重复阈值**
5. **两份定义是权威**（在 `references/` 下）——本技能第 2 节是它们的操作化版本；若冲突，以定义文件为准

**判定与处置**

| 情形 | 处置 |
|---|---|
| 达到区间 | ✅ 可交稿 |
| 低于下限但**差距 ≤10%**，且实质分析已完整 | ⚠️ **记录偏差后交付**，并在方法说明写明实际字数 |
| **低于下限且差距 >10%** | 🔴 **不得作为完整报告交付**——先逐项复查补足被压缩的核心能力；仍不足则降级为「有限披露报告」并**在封面标明** |
| 超过上限 | 检查重复结论与同义改写，**不为凑篇幅补无效解释** |

> ⚠️ **不得为贴线补字**——这是**完整度检查线，不是写作配额**。
> ⚠️ **必须真实统计并记录**：交稿时在《方法与数据来源说明》写明"正文实测 __ 汉字"。

**测量方式（必须真跑，不许估）**

```powershell
.\count-body.ps1 -Path 报告.md -Type industry     # 或 chain / mixed
```

> 退出码 0 = 达标或允许偏差内；1 = 不达标。**不计入**：附录、方法与数据来源说明、代码块。

**报告模式三档（资料不足时必须降级并标明）**

| 模式 | 何时用 | 交付要求 |
|---|---|---|
| **完整专项报告** | 资料可支撑十一节 | 覆盖全部适用节 |
| **有限披露报告** | 关键资料确实不足 | **仍须充分分析现有证据**，不得只交缺口清单；**封面标明"有限披露"** |
| **局部答复** | 用户明确只要某一个或几个问题 | 只展开相关节，不假装完整 |

#### 6.4.2 材料"正文状态"四档（**防"用摘要冒充已读原文"**）

材料索引中**每条材料必须标一档**：

| 档位 | 含义 | 能否作为结论依据 |
|---|---|---|
| **全文** | 已取得并读取完整正文 | ✅ 可以 |
| **摘录** | 只读取了关键段落/表格 | ⚠️ 可以，但引用时须标"摘录" |
| **仅摘要** | 只看到搜索摘要或二手转述 | 🔴 **不得作为关键结论的唯一依据** |
| **仅元数据** | 只有标题、来源、日期、链接 | 🔴 **只能作线索** |

> 🔴 **禁止用搜索摘要冒充已读原文**——这是本技能实测过的失真来源之一。
> ⚠️ 关键结论（决定可投性、阶段标签、出清档位的数字）**必须是"全文"或"摘录"**；若只有"仅摘要"，须在报告中标明该结论的证据强度。

## 七、边界

| 不做 | 因为 | 该用什么 |
|---|---|---|
| 阶段／出清／矩阵的判据推演 | **判据已内置**（`references/阶段判定与投资含义.md`、`references/产业链与出清机制.md`），不必外求 | 本技能自带资源 |
| 企业维度（公司画像／财务三表／估值／治理） | 那是企业的另一套方法，本技能只做行业与产业链 | hehe 系技能或专门技能 |
| 只判阶段不涉及报告 | 那是另一种问题 | `industry-lifecycle-analyzer` |
| 凭猜测选定类型 | 类型选错→整份报告答错问题 | **询问用户** |

**输出结尾必须声明**：本次调研的**类型选择依据**（显式词／指向／用户确认）、**先决条件核查结果**、以及**正文实测字数**——以便读者判断报告是否回答了正确的问题、是否达到完整度。
