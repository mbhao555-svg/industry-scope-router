# industry-scope-router —— 行业 / 产业链 调研路由器

**先判层面 → 判不出就问 → 按类型出对应报告。**

用户问的是"**行业**"还是"**产业链**"？这两者回答的**不是同一个问题**：

| | **行业调研** | **产业链调研** |
|---|---|---|
| 分析单位 | 行业（统计分类口径） | 产业链（价值流转） |
| 回答 | 这个行业**整体**值不值得进 | 这条链上**投哪一段、绕开哪一段** |
| 一句话 | 判**这门生意** | 判**这条链的位置** |

本技能负责**判断该出哪一种**；**判不出来就问你**，不猜。

## 它做什么

| 能力 | 内容 |
|---|---|
| **路由** | 三层判定：显式词 → 问题指向 → **先决条件核查** |
| **询问** | 判不出时给三选项（行业／产业链／两者都要）**并说明各自代价** |
| **骨架** | 行业调研报告 **10 节**、产业链调研报告 **11 节**（各自含"必备产出"与"不要求"） |
| **强制规则** | 两层判断混用时**必须**加声明段（否则读者无法判断是否自相矛盾） |
| **术语纪律** | 8 条禁写模式，防"行业／产业不分"（如"某行业的上游"→"某产业的上游"） |

## 关键判据：先决条件核查（四步）

⚠️ **常见误解**：以为"对象没有专门行业代码"就不能做行业报告。**这是错的。**

反例对比：

| | 预制菜 | 虾滑 |
|---|---|---|
| 专门代码 | 无 | 无 |
| **归属路径** | ⚠️ **边界有争议**（"预包装菜肴"是否含半成品未定） | ✅ **清晰**（C136 水产品加工 / C1432 速冻食品制造） |
| **目标行业统计** | ⚠️ 模糊 | ✅ **两个行业都有官方统计** |
| 结论 | **行业报告数据基础不足** | ✅ **行业报告可行** |

**四步**：① 有无专门代码？无则继续 ② **能否明确归入有效代码？** ③ **目标行业有无官方统计？** ④ 是否真是一条链？

## 它不做什么

| 不做 | 该用什么 |
|---|---|
| 阶段判定／出清机制／投资含义矩阵的**判据本体** | `industry-report-structure` / `industry-deep-research` |
| 检索取证 | `industry-deep-research` |
| 只判阶段（不涉及报告形态） | `industry-lifecycle-analyzer` |
| **凭猜测选定类型** | **询问用户** |

## 实测案例

- **预制菜** → 无专门代码且归属边界有争议 → 技能**先告知限制**，产出**产业链调研报告**（逐环节：上游调味品 37.90%–50.44% 为中游 9.03%–20.24% 的 2–5 倍）
- **虾滑** → 无专门代码但归属清晰 → 产出**行业调研报告**（阶段：成长期后段；核心变量：**GB/T 44980-2024《冻虾滑》2025-07-01 实施**，强制虾肉 >50%）

**同一个"虾滑"，问"行业前景"走行业报告、问"链上哪段"走产业链报告——两份报告结构与结论完全不同，且都成立。**
